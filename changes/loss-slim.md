Changed

The save-loss report is rewritten small (record 0010, decision 2, step 5). It now lives in `crates/carrysheet/src/save/loss.rs` and reads packages with the `zip` crate at the version GridCraft pins, not with carrysheet-zip. The JSON fields of `save` and the error codes are the same. A part that reads far more packed bytes than it unpacks, or reads 16 KiB in a row without output, is still refused with "unpacks far more slowly" inside the time limit (issue 80). What a reader can notice: `save.lost` is now one list sorted by feature name, with any "not checked" entry last; when the content inside parts cannot be searched, one entry "content inside rewritten parts (not checked: ...)" replaces the extra entry that named the counts inside sheets; several reasons in one entry are joined in alphabetical order; counts inside sheets match elements by local name and skip XML comments; and the reasons a package cannot be listed use the `zip` crate's words. The old report stays in the history of `main`: the last commit that holds it is `895dee5` (`crates/carrysheet/src/kernel/package.rs`), as does every commit before this change.
