Changed

csv files keep what they say (record 0006, record 0010 decision 3). A field becomes a number only when the number prints back as the same text, so `007`, `1E5`, `+1`, `12345678901234567890`, `SEPT1` and dates stay text; before, `007` became 7. A plain decimal such as `12.50` or `-3.00` becomes a number in a fixed-decimal format that prints it back as written, so sums count it and a save writes `12.50` again; `-0` stays text. The encoding comes from a byte order mark, else UTF-8, else a guess by `chardetng` (GBK, Big5, Shift_JIS and others); before, bytes that were not UTF-8 were read as Windows-1252. Bytes the encoding cannot hold are a `damaged_file` error instead of replacement characters. When the encoding was guessed, the book carries a warning that names it. A guess on a file of a few characters can be wrong; such a file opens as text in another encoding. Text in a file named `.xlsb` is now refused as damaged, as `.xlsx` already was.
