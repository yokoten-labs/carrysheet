Changed

Read errors have one wording for workbooks and for `--ops @file`: "<path> could not be read", with the reason (no such file, access refused, not a regular file, too large, or the system's own message) and a fix. The codes for a workbook stay as they were. For `@file`, a file over 16 MB is now `limit_exceeded` (was `invalid_argument`) and a refused access is `permission_denied` (was `io`). A missing input workbook is no longer checked before everything else: a missing confirmation, an output problem or an extension Carrysheet does not open is reported first. `commands --json` has no `implemented` field any more, since every listed command is built. A path beside the home folder, such as `/home/alicex` for the home `/home/alice`, may now show as `~x`: paths use the same matcher as other text, which hides more, never less. A home folder on a network share is also hidden after a `\\?\UNC\` prefix in free text. `ReadFailure` left the library, as its last piece of file access (record 0010, decision 2).
