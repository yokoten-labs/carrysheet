Changed

`edit` checks a formula on GridCraft's own parse tree, the tree the kernel stores, instead of our own tokenizer (record 0010, decision 2, step 6). The list of refused functions is the same. A formula that does not parse, such as `=SUM(A1;A2)`, now gets its own message: "ops[i] has a formula Carrysheet cannot read", with the parser's reason and the fix "Correct the formula (use , between arguments) and call again; nothing was saved." Before, it failed later with "could not be applied". Links to other workbooks and DDE still do not parse, so they are still refused. A structured reference into another file, such as `Book.xlsx!Table1[Col]`, is now refused too. Operations are read through the argument structs: an unknown operation, a negative `count` or a `count` too large now gets "ops is not a list of operations". The code stays `invalid_argument`. Removed from the library, unused in the workspace: `EditKind::parse`, `EditKind::as_str`, `EditKind::is_sheet_op`, `EditKind::is_structural` and `FileFormat::as_str`; `edit::Scalar` is now `args::Scalar`, whose `Bool` is named `Flag`. The old code stays in the history of `main`, for example in `deca503` (`crates/carrysheet/src/edit.rs`).
