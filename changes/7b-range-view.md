Removed

`overview` no longer shows a header row for each sheet: the `sheets[].header` field is gone (record 0010, decision 11, point 1). `overview` no longer takes `response_format`, which only widened that row: a call that still passes it is refused, with `invalid_argument` over MCP and a usage error on the command line. This breaks any caller that sent it. To see a sheet's first row, call `read` with a range like `'Name'!1:1`. When more sheets exist than `overview` lists, `sheets_total` and the hint stay. Ranges are now read by GridCraft's own parser (record 0010, decision 6). A `$` in a range is still accepted, but it is not written back: `$A$1:B2` comes back as `A1:B2`. A range that cannot be read gets one error text: "write cells like B7 or A1:C10, whole columns like A:C, or whole rows like 2:5; columns go from A to XFD, rows from 1 to 1048576". Before, a column past XFD and a row outside 1 to 1048576 had their own texts. Sheet names in references are quoted by GridCraft's rule: a name of letters in any script, such as `売上`, is no longer quoted (`売上!A1`). A quoted name still reads. A column range written as cells, such as `A1:A1048576`, comes back as `A:A`. Removed from the library, unused in the workspace: `range::sheet_name_needs_quotes`, `range::cells_text`, `ReadMode::parse`, `ReadCursor::rest_of_band` and `ReadCursor::sheet`. The removed code stays in the history of `main`: `4defaae` has it (`crates/carrysheet/src/range.rs`, `crates/carrysheet/src/view.rs`).
