Removed

The save-loss report no longer looks inside parts (record 0010, decision 11, cut 2). It compares the opened file and the file to be written by part name and size, from the zip directory, and still lists dropped parts, features found by part name, the part counts, and the notes for a rebuilt cache and a digital signature. The entries for content inside rewritten parts are gone: `file sharing settings`, `workbook code name (VBA)`, `sheet code names (VBA)`, `AutoFilter settings`, `AutoFilter sort`, `phonetic settings`, `hyperlink text and tips`, `rich text in cells`, `phonetic guides`, `people of threaded comments (user ids)`, `formula results (they would become #NAME?)`, `newer Excel function names (_xlfn.)`, and `content inside rewritten parts (not checked: ...)`. GridCraft keeps that content on save, and a test proves it. The save check unpacks only `[Content_Types].xml`, for `overview`'s `macros` field, and only when its sizes in the zip directory are within bounds; so it never reads a padded part (issue 80). `edit` still reports what it drops because the cells moved or were overwritten: `scenarios`, `ignored error flags`, `what-if data tables` and `formatted note text`, and the save still needs `confirm_loss`. A save to csv counts conditional formatting, data validation, sparklines, hyperlinks and merged cells of the sheet it writes, and the defined names, from GridCraft's model; so .xls and .xlsb sources are counted too. Writing `.xls` was never built: an `.xls` output is now `unsupported_format` instead of `not_implemented`, and `format` takes `xlsx` or `csv`. A sheet name for `add_sheet` or `rename_sheet` is checked by GridCraft when the operation runs, so a bad name fails as "ops[i] (add_sheet) could not be applied" with GridCraft's reason; a control character is still refused when the operations are read. A sheet that does not exist now reads "ops[i]: there is no sheet named ...". The search stays in the history of `main`: `4defaae` has it (`crates/carrysheet/src/save/loss.rs`).
