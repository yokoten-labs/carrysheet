# Changelog

Changes people and scripts notice, newest first. Commands, arguments and
error codes are the public interface (`carrysheet-cli commands --json`).

## [Unreleased]

## [0.1.0] - 2026-11-27

The first release: `carrysheet-cli`, a command-line tool and MCP server for Windows, Linux and macOS. It reads, edits and converts spreadsheets (`.xlsx`, `.xlsm`, `.xls`, `.xlsb`, `.ods`, `.csv`) and says what a save would lose. Its own code is under 5,000 lines (record 0011).

### Changed

- `overview` no longer takes `response_format`; it only widened the header row, which `overview` no longer shows (record 0010, decision 11). A call to `overview` that still passes `response_format` is now refused: `invalid_argument` over MCP ("`overview` has no argument named `response_format`"), a usage error on the command line. This breaks any caller that sent it. The `confirmation_required` error no longer repeats the whole call in its fix: it says to call again with the same arguments and `"confirm":true`, or to add `--confirm` on the command line. The error code `declined` is gone; nothing asks a question any more, so no command returned it. The texts of `convert` name xlsx and csv only. Removed from the library, unused in the workspace: `text::terminal`, `text::has_hidden`, `text::UNICODE_VERSION` and `ErrorCode::Declined`. They stay in the history of `main`: `4defaae` has them (`crates/carrysheet/src/text.rs`, `crates/carrysheet/src/error.rs`).
- Read errors have one wording for workbooks and for `--ops @file`: "<path> could not be read", with the reason (no such file, access refused, not a regular file, too large, or the system's own message) and a fix. The codes for a workbook stay as they were. For `@file`, a file over 16 MB is now `limit_exceeded` (was `invalid_argument`) and a refused access is `permission_denied` (was `io`). A missing input workbook is no longer checked before everything else: a missing confirmation, an output problem or an extension Carrysheet does not open is reported first. `commands --json` has no `implemented` field any more, since every listed command is built. A path beside the home folder, such as `/home/alicex` for the home `/home/alice`, may now show as `~x`: paths use the same matcher as other text, which hides more, never less. A home folder on a network share is also hidden after a `\\?\UNC\` prefix in free text. `ReadFailure` left the library, as its last piece of file access (record 0010, decision 2). `ReadFailure`, `files::Step` and `files::display_path_text` stay in the history of `main`: `4defaae` has them (`crates/carrysheet/src/open.rs`, `apps/carrysheet-cli/src/files.rs`).
- `mcp serve` keeps stdout for JSON-RPC from the start, also with `--json`: an error before the session, such as a folder too wide to serve without `--root`, is now text on stderr only, where it was also a JSON document on stdout before. Clap errors such as an unknown flag stay JSON with `--json`. The text of a usage error is unchanged: clap's first paragraph without `error: ` is the what, its tips, possible values and usage line are the fix, the code is `usage` and the exit code 2. Inside, one function builds a usage error, `main` decides who writes stdout instead of a static flag, and the MCP server holds its root and offered commands as plain fields. The removed stdout flag (`reserve_stdout_for_mcp`) and `clap_message` stay in the history of `main`: `4defaae` has them (`apps/carrysheet-cli/src/output.rs`, `apps/carrysheet-cli/src/mcp.rs`).
- Without `--json`, every command prints one plain text form (record 0010, decision 2): a list of rows is a table with tab-separated columns, and every other field is `key: value`, with nested fields indented. The hand-written text of each command is gone, so `overview`, `read`, `eval` and the edit commands show their fields in the same layout as their JSON. `eval` prints `formula`, `value`, `kind` and `file` lines, such as `value: 15`, instead of the bare value. `commands` prints a two-column table of command and summary. A usage error now carries clap's own message in the same error, fix and why lines, and the fix holds clap's suggestion and usage line. Running `carrysheet-cli` with no command prints clap's help on stderr and exits 2. In the text form, a value longer than 2,000 characters ends in `...`; `--json` still shows it whole. In `--json`, the success output does not change, but the `why` and `fix` text of usage errors does: `why` is now always "the command line was not understood", and `fix` holds clap's own tip, possible values and usage lines instead of the tailored sentences.
- Each command's arguments are now one Rust struct: the single source of its flags, its MCP tool schema and its help (record 0010, decisions 2 and 6). The MCP tool list and `commands --json` do not change by one character. Some messages read differently. In `--help` and in usage errors, a flag's value shows the flag's name in capitals, such as `--max-rows <MAX_ROWS>` and `--mode <MODE>` (before: `<N>` and `<mode>`), and an argument's help line has no full stop at the end. The reason in an error about a wrong argument now comes from the type check, such as `invalid type: string "abc", expected u32` (before: `` `max_rows` must be a whole number from 1 to 10000, but it is the text "abc" ``), and is cut at 300 characters. Its fix line still says what to send, such as `` Give `format` as one of xlsx, xls, csv. ``, and then gives the argument's description. An error inside `ops` names the operation, such as `ops[2]`, and no longer the field inside it; its fix line lists an operation's fields with an example. On the command line, a negative number such as `--max-rows -5` is now a usage error from the flag parser. Error codes and exit codes do not change. The command table, the schema writer and the validator are gone (`crates/carrysheet/src/commands/table.rs` and `commands/schema/`). The code stays in the history of `main`, for example in `895dee5`.
- csv files keep what they say (record 0006, record 0010 decision 3). A field becomes a number only when the number prints back as the same text, so `007`, `1E5`, `+1`, `12345678901234567890`, `SEPT1` and dates stay text; before, `007` became 7. A plain decimal such as `12.50` or `-3.00` becomes a number in a fixed-decimal format that prints it back as written, so sums count it and a save writes `12.50` again; `-0` stays text. A field with more than 15 significant digits, such as the card number `4111111111111111`, or more than 30 decimals stays text, since Excel would show it changed. The encoding comes from a byte order mark, else UTF-8, else a guess by `chardetng` (GBK, Big5, Shift_JIS and others); before, bytes that were not UTF-8 were read as Windows-1252. Bytes the encoding cannot hold are a `damaged_file` error instead of replacement characters. When the encoding was guessed, the book carries a warning that names it. A guess on a file of a few characters can be wrong; such a file opens as text in another encoding. Text in a file named `.xlsb` is now refused as damaged, as `.xlsx` already was.
- `edit` checks a formula on GridCraft's own parse tree, the tree the kernel stores, instead of our own tokenizer (record 0010, decision 2, step 6). The list of refused functions is the same. A formula that does not parse, such as `=SUM(A1;A2)`, now gets its own message: "ops[i] has a formula Carrysheet cannot read", with the parser's reason and the fix "Correct the formula (use , between arguments) and call again; nothing was saved." Before, it failed later with "could not be applied". Links to other workbooks and DDE still do not parse, so they are still refused. A structured reference into another file, such as `Book.xlsx!Table1[Col]`, is now refused too. Operations are read through the argument structs: an unknown operation, a negative `count` or a `count` too large now gets "ops is not a list of operations". The code stays `invalid_argument`. Removed from the library, unused in the workspace: `EditKind::parse`, `EditKind::as_str`, `EditKind::is_sheet_op`, `EditKind::is_structural` and `FileFormat::as_str`; `edit::Scalar` is now `args::Scalar`, whose `Bool` is named `Flag`. The old code stays in the history of `main`, for example in `deca503` (`crates/carrysheet/src/edit.rs`).
- `edit` without `output` writes `name-edited.xlsx` beside the original, as before, but no longer tries `name-edited-2.xlsx` and on up to `-99` when that name is taken. It refuses with `file_exists` instead: pass `output` with another name, or `output` and `overwrite` with `confirm` to replace it. A `dry_run` writes nothing, so it never fails over a taken name. The numbered names stay in the history of `main`: `4defaae` has them (`crates/carrysheet/src/save.rs`).
- File access moved from the library into the program (record 0010, decision 2). `carrysheet::run` now takes the file's bytes and gives back an `Answer` with the JSON fields and, for a save, the bytes to write; `Kernel::open` is gone, and the library's errors no longer replace the home folder with `~`. `carrysheet-cli` does that for every error, log line and path it shows, and `--root` works as before on the command line and over MCP. What a user can notice: a call with a bad argument and also a file that cannot be used now names the file's problem first; `edit` reports an existing output file before an error in `ops`; and on the command line an output path that is a broken link is replaced by a regular file instead of written through. A workbook that is too large is still refused from its size, before any byte is read.
- The save-loss report is rewritten small (record 0010, decision 2, step 5). It now lives in `crates/carrysheet/src/save/loss.rs` and reads packages with the `zip` crate at the version GridCraft pins, not with carrysheet-zip. The JSON fields of `save` and the error codes are the same. A part that reads far more packed bytes than it unpacks, or reads 16 KiB in a row without output, is still refused with "unpacks far more slowly" inside the time limit (issue 80). What a reader can notice: `save.lost` is now one list sorted by feature name, with any "not checked" entry last; when the content inside parts cannot be searched, one entry "content inside rewritten parts (not checked: ...)" replaces the extra entry that named the counts inside sheets; several reasons in one entry are joined in alphabetical order; counts inside sheets match elements by local name and skip XML comments; and the reasons a package cannot be listed use the `zip` crate's words. The old report stays in the history of `main`: the last commit that holds it is `895dee5` (`crates/carrysheet/src/kernel/package.rs`), as does every commit before this change.
- `carrysheet-cli mcp serve` no longer forwards rmcp's internal tracing messages to stderr (record 0010, decision 2, step 6). Carrysheet's own log lines are the same: start, stop, failed calls, the `--root` warning and panics, all on stderr. stdout still carries only JSON-RPC, and `tools/list` is the same text. A stop for a reason other than a closed stdin is logged in rmcp's words, such as `Cancelled`. On the command line, an `@file` argument that cannot be read has one fix for a missing file and for an unreadable one: "Check the file path after @ and that you can read it, or pass the JSON itself to --ops." The codes `file_not_found` and `io` are the same. The forwarder stays in the history of `main`, for example in `deca503` (`apps/carrysheet-cli/src/mcp.rs`).
- A range whose sheet name breaks Excel's rules, such as `'a:b'!A1` or `'History'!A1`, now fails with `no_such_sheet` instead of `invalid_reference`, because no sheet has that name. An empty name, as in `!A1` or `''!A1`, is still `invalid_reference`. The name in that error is quoted and escaped, so control characters show as escapes; this also covers the targets of `rename_sheet` and `delete_sheet`. The exit code is now 1, where it was 2. The error code `not_implemented` is gone; no command returned it. The removed check stays in the history of `main`: `4defaae` has it (`crates/carrysheet/src/range.rs`).

### Removed

- **Everything outside the 5,000-line cap** (record 0010 and record 0011):
  the `macros` command, MCP over HTTP, `feedback`, our own readers that no
  program linked (old `.xls`, Numbers, csv, encryption, data connections,
  SQL) and `tools/`; thirteen crates became two. GridCraft now reads every
  format. The removed code stays in the history of `main`: `50bd07b` is the
  last commit on `main` before the first deletion merged, and holds all of
  it. Code rewritten or removed later in the cut, such as `eval`, is named
  in its own `changes/` file.
- `overview` no longer shows a header row for each sheet: the `sheets[].header` field is gone (record 0010, decision 11, point 1). `overview` no longer takes `response_format`, which only widened that row: a call that still passes it is refused, with `invalid_argument` over MCP and a usage error on the command line. This breaks any caller that sent it. To see a sheet's first row, call `read` with a range like `'Name'!1:1`. When more sheets exist than `overview` lists, `sheets_total` and the hint stay. Ranges are now read by GridCraft's own parser (record 0010, decision 6). A `$` in a range is still accepted, but it is not written back: `$A$1:B2` comes back as `A1:B2`. A range that cannot be read gets one error text: "write cells like B7 or A1:C10, whole columns like A:C, or whole rows like 2:5; columns go from A to XFD, rows from 1 to 1048576". Before, a column past XFD and a row outside 1 to 1048576 had their own texts. Sheet names in references are quoted by GridCraft's rule: a name of letters in any script, such as `売上`, is no longer quoted (`売上!A1`). A quoted name still reads. A column range written as cells, such as `A1:A1048576`, comes back as `A:A`. Removed from the library, unused in the workspace: `range::sheet_name_needs_quotes`, `range::cells_text`, `ReadMode::parse`, `ReadCursor::rest_of_band` and `ReadCursor::sheet`. The removed code stays in the history of `main`: `4defaae` has it (`crates/carrysheet/src/range.rs`, `crates/carrysheet/src/view.rs`).
- The save-loss report no longer looks inside parts. This is wider than record 0010, decision 11, point 2, which cuts only the counts inside sheets and keeps the part-level report; the owner has yet to decide the wider cut. It compares the opened file and the file to be written by part name and size, from the zip directory, and still lists dropped parts, features found by part name, the part counts, and the notes for a rebuilt cache and a digital signature. The entries for content inside rewritten parts are gone: `file sharing settings`, `workbook code name (VBA)`, `sheet code names (VBA)`, `AutoFilter settings`, `AutoFilter sort`, `phonetic settings`, `hyperlink text and tips`, `rich text in cells`, `phonetic guides`, `people of threaded comments (user ids)`, `formula results (they would become #NAME?)`, `newer Excel function names (_xlfn.)`, and `content inside rewritten parts (not checked: ...)`. GridCraft keeps that content on save, and a test proves it. What is lost: if GridCraft drops content inside a part it rewrites, the save no longer finds it at run time. The save check unpacks only `[Content_Types].xml`, for `overview`'s `macros` field, and only when its sizes in the zip directory are within bounds; so it never reads a padded part (issue 80). `edit` still reports what it drops because the cells moved or were overwritten: `scenarios`, `ignored error flags`, `what-if data tables` and `formatted note text`, and the save still needs `confirm_loss`. A save to csv counts conditional formatting, data validation, sparklines, hyperlinks and merged cells of the sheet it writes, and the defined names, from GridCraft's model; so .xls and .xlsb sources are counted too. Writing `.xls` was never built: an `.xls` output is now `unsupported_format` instead of `not_implemented`, and `format` takes `xlsx` or `csv`. A sheet name for `add_sheet` or `rename_sheet` is checked by GridCraft when the operation runs, so a bad name fails as "ops[i] (add_sheet) could not be applied" with GridCraft's reason; a control character, or a name longer than 31 UTF-16 units (as Excel counts), is still refused when the operations are read. A sheet that does not exist now reads "ops[i]: there is no sheet named ...". The search stays in the history of `main`: `4defaae` has it (`crates/carrysheet/src/save/loss.rs`).
- The `macros` command and its readers (`carrysheet-vba`, `carrysheet-cfb`), MCP over HTTP (`mcp serve --http`, `--token-file`, `--allow-writes`, `docs/mcp-http.md`), `mcp serve --log-file`, the `feedback` command, the placeholders `check`, `sanitize`, `mcp install` and `mcp doctor` (issue 102), and the y/N question at a terminal. Nobody is asked any more: a call that needs a confirmation fails with a three-part error that names `--confirm`, `--confirm-loss` and `--yes`. The MCP server logs to stderr only, cleaned like text from a file. `overview` gains a `macros` field when an .xlsx, .xlsm or .xlsb file holds a VBA project or Excel 4 macro sheets, found by part name and by content type, so a renamed part is found too: they are never run, and a save keeps them where the format can hold them. For .xls and .ods files, a zip it cannot list, and content types it cannot read or that use character references or UTF-16, the field says macros were not checked. `deny.toml` now bans HTTP and TLS crates and fences GridCraft to `carrysheet-kernel` and rmcp and tokio to `carrysheet-cli`. The code stays in the history of `main`: `47dfd01` has it, as does every commit before this change (record 0010, decision 4, step 2).
- The file readers that no program links: `carrysheet-biff`, `carrysheet-csv`, `carrysheet-crypto`, `carrysheet-numbers`, `carrysheet-connections` and `carrysheet-query`, with `tools/bench`, `tools/fuzzlite`, `tools/excel-ground-truth` and the optional `query` feature of `carrysheet-cli`. Their sample files moved to `crates/carrysheet-kernel/tests/data/formats/`. The code stays in the history of `main`: `364adbb` is the last commit that changed it, and every commit before this change still has it. `carrysheet-cli` behaves as before (record 0010, decision 4, step 1).
- The `eval` command and its MCP tool are gone, to bring the product under the 5,000-line cap (record 0011, which amends record 0010, decision 11). To see what a formula computes, call `edit` with `dry_run`: set the formula in a free cell, and the change list shows its value, like `{"formula": "=SUM(B2:B9)", "value": 150}`. Nothing is written. The MCP tool list is now `overview`, `read`, `convert` and `edit`; with `--read-only` it is `overview` and `read`. The error code `formula`, which only `eval` returned, is gone. The hint for cut text in `read` now names `edit` with `dry_run` and `MID`. The removed code stays in the history of `main`: `4defaae` has it (`crates/carrysheet/src/view.rs`, `crates/carrysheet/src/args.rs`).
- The layers between the commands and GridCraft: the `Engine` trait and `SheetView`, the memory engine with the `test-engine` feature, and the `model` module with its own cell, value and workbook types. The library is now `lib.rs` (one command, the limits, the caught panic), `open.rs`, `view.rs`, `edit.rs`, `save.rs`, `range.rs` and `error.rs`; cells and ranges are GridCraft's `CellRef` and `RangeRef`, and `range.rs` adds only the sheet name, the `$` marks and the reasons. `carrysheet-cli` prints the same JSON, error codes and exit codes. Two things differ for a range that was already refused or odd: a range that is not cells, whole columns or whole rows gets one reason instead of several, and a row number written with more than 7 digits (`A00000001`) is refused. The code stays in the history of `main`: the last commit that holds it is 18e312f, and every commit before this change still has it, in `crates/carrysheet/src/commands/engine` and `crates/carrysheet/src/model` after step 3, and in `crates/carrysheet-commands`, `crates/carrysheet-kernel` and `crates/carrysheet-model` before it (record 0010, decision 4, step 4).
- The crates `carrysheet-commands`, `carrysheet-kernel` and `carrysheet-model`, folded into one library crate, `carrysheet`, as its modules `commands`, `kernel` and `model`; `carrysheet-cli` depends on it. Unit tests moved out of the code files into `src/tests/`. Also removed: `scripts/check.mjs`, `scripts/check.test.mjs`, `scripts/output.mjs` and `scripts/release-check.mjs`. CI now runs plain cargo steps, and the Rust version is pinned in `rust-toolchain.toml`. The release privacy scan still checks a Linux release build for the home folder, `/home/` paths, the user name and email addresses. `carrysheet-cli` behaves as before. The old crates and scripts stay in the history of `main`: `275442a` is the last commit that has them, as does every commit before this change (record 0010, decision 4, step 3).
- The answer of `edit` no longer has the `recalculated` and `recalculated_total` fields, which listed formula cells whose result changed because of the edit (record 0011). `changes` still lists every cell the operations wrote, with a new formula's value. To see a formula elsewhere after an edit, `read` it, or set it in a free cell with `edit` and `dry_run`. The list stays in the history of `main`: `4defaae` has it (`crates/carrysheet/src/edit.rs`).
- The save report of `edit` and `convert` no longer has a `parts` field with counts of identical, rewritten, dropped and added package parts (record 0011). What a save loses is still reported: `lost` by feature, `dropped_parts` by name, and `notes` for parts Excel rebuilds. The counts stay in the history of `main`: `4defaae` has them (`crates/carrysheet/src/save.rs`, `crates/carrysheet/src/save/loss.rs`).
- The library's own `Limits` struct, with its `Default` and its conversion to GridCraft's limits (record 0010, decision 2, step 6). `carrysheet::Limits` is now GridCraft's limits type, and `carrysheet::LIMITS` holds Carrysheet's values. Also removed from the library, unused in the workspace: `view::CellInfo` and `view::requested_sheet`. `carrysheet-cli` prints the same JSON, error codes and exit codes. The crate stays in the history of `main`: the last commit that holds it is `895dee5` (`crates/carrysheet-zip`), as does every commit before this change (record 0010: decision 4 lists the zip crate among what leaves with `macros`, and decision 2 keeps two crates, `carrysheet` and `carrysheet-cli`).

### Breaking changes for scripts

- **Saving content a file would lose needs `confirm_loss`.** `edit` and
  `convert` refuse to save when the written file would lack something the
  source held (macros, charts, comments, content the save check could not
  search...). Pass `confirm_loss: true` (`--confirm-loss` on the command
  line) after reading `save.lost` from a `dry_run`. `confirm` no longer
  covers this: it only agrees to deleting sheets, rows or columns, or to
  overwriting a file. `--yes` gives both.
- **CSV output escapes formula-like text by default.** Text starting with
  `=`, `+`, `-` or `@` is written with a leading `'`, so spreadsheet apps
  do not run it. Pass `csv_raw: true` (`--csv-raw`) for the old output.
- **One command may take 10 seconds by default.** The limit covers the
  whole command: opening, calculating and saving. A command that runs out
  fails with `limit_exceeded` and writes nothing. On the command line,
  `--max-seconds N` allows up to 3,600 seconds; MCP and agent calls keep
  the 10-second limit.
- **More formula functions are refused** in `edit`, because they reach
  outside the file: `TRANSLATE`, `DETECTLANGUAGE`, `IMPORTRANGE`,
  `IMPORTHTML`, `IMPORTFEED`, `GOOGLEFINANCE` and the `CUBE...` functions,
  also when written next to a range (`A1:WEBSERVICE(...)`).
- Text from a file is escaped by one helper, `carrysheet::text`, in messages, in the sheet names and warnings of `overview`, in the text form and in the MCP log (issue 67). Cell values, headers and cursors in JSON stay as stored. Tag characters (U+E0000 to U+E007F), every other invisible or format character from a Unicode 18.0.0 table, and private use characters now show as `\u{…}`, and a backslash shows as `\\`, so file text cannot hide instructions or fake an escape. Plain text, CJK text and single emoji do not change; the joiner U+200D and the emoji selector U+FE0F in emoji sequences show as escapes. A cut text now ends in `…[cut: N more characters]` instead of `...`, and in a quoted part name the mark follows the closing quote.

### Internal

- Both crates take one version from the workspace (`version.workspace = true`), and the program depends on the library through `[workspace.dependencies]`. Each crate now carries its license files, so `cargo package` ships them: `LICENSE-MIT` and `LICENSE-APACHE` in `carrysheet`, `LICENSE-GPL` in `carrysheet-cli`. `about.toml` configures `cargo about`, which writes the third-party notices at release time. `CONTRIBUTING.md` says how a release is made from a tag; only the owner tags (issues 94, 95 and 97).
